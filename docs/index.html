The honest status

A working prototype with launch gates still closed.

The software path exists. The social, provider, deployment, and independent-review assumptions that make it a trustworthy public service do not all exist yet.

Working and tested

  • Loopback-only local web app with streaming chat and model disclosures
  • Encrypted, pinned relay with a default-deny destination allowlist
  • Blind-signed single-use request tokens and durable replay protection on Linux
  • Aggregate request, input, output, and optional cost ceilings
  • Client binaries cross-compile for Windows, Linux, and macOS; launcher syntax is checked

Still blocking public use

  • No independently operated public relay is enrolled
  • The gateway can read prompts; attested execution is not built
  • Per-invite fairness has no client wallet yet
  • The payment path has no independent security review
  • Ox Alpha integration permission and conflicting data-use language are unresolved
  • Clean native installs and OS warning paths have not passed all three platform smoke tests

One request, divided knowledge

The privacy design depends on separation, not a reassuring label.

Each component learns something. When relay and gateway actually have separate operators, this experimental design aims to prevent one operator from directly joining network identity, content, and provider account. Timing analysis or collusion can still link them.

  1. Local app

    Sees the conversation and keeps history ephemeral unless you explicitly save it in this browser.

  2. Relay

    Sees source address, timing, volume, and allowed destination—but carries encrypted content.

  3. Gateway

    Sees plaintext and a blind-signed token, but is not sent the relay-side network identity.

  4. Model provider

    Sees content under the gateway account, subject to its own retention and training policy.

Privacy boundary

What Osanwë does—and does not—hide.

Writing style, facts inside a prompt, endpoint timing, a colluding relay and gateway, and the provider's own data handling remain meaningful risks.

Provider learns
Prompt and answer; gateway account instead of tester account in token mode
Relay learns
Source address, timing, traffic volume, and constrained destination
Gateway learns
Prompt, answer, model, and a single-use token that cannot be directly cryptographically matched to its blinded issuance transcript; timing and collusion remain
Osanwë stores
No server-side conversation history; optional browser-only local history
Not yet protected
Gateway plaintext from its operator through attested execution

Website, not web chat

Download locally. Keep the public page out of the conversation.

The website explains, recruits, and will publish checksummed archives. The chat stays on 127.0.0.1; this site has no prompt box, analytics, Osanwë account system, key field, or access to local history. The separate beta application uses a public GitHub account. Invited testers receive a non-secret connection file and paste secrets only into the local launcher.
