# Code runner boundary

Code mode can load generated JavaScript and HTML into a local runner. Running code is always an
explicit action; receiving a model response never executes it automatically.

## JavaScript

JavaScript runs in a new disposable Web Worker. The worker has no DOM, receives no provider key or
conversation object, and is terminated after 2.5 seconds. Fetch, XMLHttpRequest, WebSocket,
EventSource, and nested workers are disabled in the harness. The runner document also has a Content
Security Policy with `connect-src 'none'`, and its iframe has an opaque sandbox origin.

The harness exposes two small testing helpers:

```javascript
test("addition", () => assert(2 + 2 === 4, "expected four"));
```

Console messages and pass/fail results are returned to the parent page through a per-run channel.
They are generated by untrusted code and must not be treated as a security verdict.

## HTML

HTML is a visual preview, not a browser application runtime. Before rendering, the runner removes
scripts, frames, objects, embeds, forms, external stylesheets, event-handler attributes, and
remote-loading URL attributes. Its separate Content Security Policy also blocks connections,
frames, objects, fonts, media, and non-data images.

## Deliberate limits

- No Python, shell, package installation, filesystem, local repository, terminal, or server process.
- No automatic execution of generated code.
- No network access from generated code.
- No durable runner workspace; reload clears the editor and results.
- The timeout is an availability guard, not a memory quota. Extremely memory-heavy code may still
  destabilize the browser tab.

Repository-aware execution requires a separate local broker with explicit folder permissions,
command allowlists, resource limits, secret redaction, and a review-before-apply workflow. It is not
part of this browser sandbox.
