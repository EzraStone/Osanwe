# Code runner boundary

Code mode can load generated JavaScript and self-contained web pages into a local runner. Running
code is always an explicit action; receiving a model response never executes it automatically. If
one answer contains HTML, CSS, and JavaScript fences, the interface combines them into the exact web
snapshot launched by **Run preview**.

## JavaScript

JavaScript runs in a new disposable Web Worker. The worker has no DOM, receives no provider key or
conversation object, and is terminated after 2.5 seconds. Fetch, XMLHttpRequest, WebSocket,
EventSource, and nested workers are disabled in the harness. The runner document also has a Content
Security Policy with `connect-src 'none'`, and its iframe has an opaque sandbox origin.

The harness exposes two small testing helpers:

```javascript
test("addition", () => assert(2 + 2 === 4, "expected four"));
```

Console messages and pass/fail results appear in the preview and are returned to the parent page
through a per-run channel. They are generated by untrusted code and must not be treated as a
security verdict.

## HTML

HTML runs as an interactive, self-contained web page. Generated markup is placed in a fresh nested
iframe with an opaque origin and only `allow-scripts`; it never executes in the trusted runner broker
or the credential-bearing Osanwë page. Inline styles, scripts, and event handlers can run. Forms,
frames, plugins, external stylesheets, and remote-loading attributes are removed, while a document
Content Security Policy and response-level connection policy deny network connections, nested
contexts, objects, and other remote resources.
The frame is discarded and rebuilt for each run. Bounded console output and uncaught script errors
are forwarded to the Console drawer; a synchronous error marks the run as completed with errors.

Interactive HTML is gated to Chromium 152 or newer, where the response-level connection policy is
available. Other browsers fail closed with an update message instead of running the page. Standalone
JavaScript remains available in its network-blocked worker.

Interactive HTML does not have the worker's reliable 2.5-second CPU cutoff. A page with a main-thread
infinite loop or extreme memory use may still make the browser tab unresponsive. Use JavaScript mode
for bounded algorithm and test execution.

## Deliberate limits

- No Python, shell, package installation, ambient filesystem, local repository, terminal, or server process.
- A preview can read a file only when the person deliberately selects or drops it into the generated
  page. That file remains inside the network-blocked preview and is not sent to the model, but the
  generated code can inspect it, so do not choose sensitive files.
- No automatic execution of generated code.
- No network access from generated code.
- No durable runner workspace; a page reload clears the editor, display, and results.
- Preview Reload reruns the last explicit in-memory snapshot, not unrun editor changes.
- The timeout is an availability guard, not a memory quota. Extremely memory-heavy code may still
  destabilize the browser tab.

Repository-aware execution requires a separate local broker with explicit folder permissions,
command allowlists, resource limits, secret redaction, and a review-before-apply workflow. It is not
part of this browser sandbox.
